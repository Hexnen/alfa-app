# Udostępnianie wydarzeń linkiem (kalendarz techniczny)

Stan: w realizacji (2026-10-20). Kontrakt poniżej jest wiążący dla obu stron (backend / frontend).

## Cel

W dialogu wydarzenia kalendarza technicznego, w stopce: **ikonka kosza (sam Trash2, bez napisu „Usuń”, z `aria-label`/tooltipem) + po jej prawej ikonka „Udostępnij”** (lucide `Share2`). Klik otwiera modal **„Udostępnij”**:
1. wybór odbiorcy: **technik** (lista `technicians`, przypisani do wydarzenia na górze) ALBO **Gość** — wtedy imię/nazwa odbiorcy jest **wymagane** (tak wiadomo, kto dostał link);
2. wybór ważności (domyślnie: „do 7 dni po zakończeniu wydarzenia”; opcje: 24 h od teraz, 7 dni po wydarzeniu, 30 dni od teraz);
3. „Utwórz link” → pokazuje pełny URL (kopiuj; na telefonie dodatkowo `navigator.share`, jeśli dostępne). **URL widać tylko raz** — w bazie jest sam hash;
4. pod spodem lista dotychczasowych linków tego wydarzenia: odbiorca, utworzył/kiedy, ważny do, liczba otwarć + ostatnie otwarcie, status, przycisk **Unieważnij**.

Odbiorca linku widzi ekran zlecenia **jak w panelu technika, ale tylko do odczytu, bez logowania**.

## Decyzje (z researchu 2026: W3C „Good Practices for Capability URLs”, Shopify secure tokens, praktyki share-linków)
- Token: `crypto.randomBytes(32)` → base64url (256 bit). W DB tylko `sha256(token)` (hex). Porównanie po hashu w zapytaniu (indeks unikalny).
- Odwoływalny (`revoked_at`), z terminem (`expires_at`), licznik otwarć. Wygasły/odwołany/nieistniejący/wydarzenie usunięte → **to samo 404** (nie zdradzamy różnicy).
- Odpowiedzi publiczne: `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`. Strona frontowa też `<meta name="referrer" content="no-referrer">` i `noindex`.
- Rate limit na publiczny endpoint (per IP, np. 60/min) — token i tak jest niezgadywalny, to tylko higiena.
- **Tylko odczyt.** Brak start/finish/notatek/protokołu/zdjęć. Widok = `JobJson` z `src/routes/technik.ts` (wąski typ bez kwot/billingu/wycen) **bez notatek i bez protokołu** (notatki to wewnętrzna rozmowa biura/techników).
- Dostęp bez ownership technika: link jest sam w sobie uprawnieniem do JEDNEGO wydarzenia (`event_id`), niczego więcej. Typ `notatka` nie jest udostępnialny (technik go też nie widzi). Wydarzenie usunięte (soft delete) → 404.
- Uprawnienia tworzenia/listy/odwołania: poziom `edit` na `technical/kalendarz` (jak edycja wydarzenia).
- Audyt „kto dostał”: wpis w `activity_log` (`src/lib/activity-log.ts`) przy utworzeniu i odwołaniu: „Udostępniono link: <odbiorca>”.

## Dane (migracja 0117 — UWAGA na kolejność po `when`, patrz pamięć `migration-when-ordering`)
Tabela `calendar_event_shares`:
`id` PK, `event_id` FK→calendar_events (cascade), `token_hash` TEXT UNIQUE, `technician_id` INTEGER NULL (FK technicians, set null), `recipient_name` TEXT NOT NULL (dla technika = jego nazwa w momencie tworzenia; dla gościa = wpisane), `created_by_user_id`, `created_by_label` TEXT, `created_at` TEXT, `expires_at` TEXT NOT NULL (ISO UTC), `revoked_at` TEXT NULL, `open_count` INTEGER DEFAULT 0, `last_opened_at` TEXT NULL. Indeks na `event_id`.

## API
Zalogowane (router kalendarza, `src/routes/calendar.ts` albo osobny `calendar-shares.ts` montowany obok; wymaga `edit`):
- `GET    /api/calendar/events/:id/shares` → `{ success, data: ShareRow[] }`
- `POST   /api/calendar/events/:id/shares` body `{ technicianId?: number, recipientName?: string, expiresIn: "24h"|"event+7d"|"30d" }` → `{ success, data: { share: ShareRow, url: string, token: string } }`. Walidacja: albo `technicianId` (istniejący), albo niepuste `recipientName` (1–80 znaków, trim). `url` = `<origin>/u/<token>`; origin z `PUBLIC_BASE_URL`/nagłówków jak robi to feed ICS (sprawdzić istniejący wzorzec); front i tak składa URL z `window.location.origin` + `token`.
- `DELETE /api/calendar/events/:id/shares/:shareId` → ustawia `revoked_at` (idempotentnie).
`ShareRow` = `{ id, eventId, technicianId: number|null, recipientName, createdByLabel, createdAt, expiresAt, revokedAt: string|null, openCount, lastOpenedAt: string|null, status: "active"|"expired"|"revoked" }` (bez hasha i tokena).

Publiczne (montowane PRZED `requireAuth`, jak feed ICS; bez cookie; rola `technik` i `technikRoleGuard` nie dotyczą):
- `GET /api/share/:token` → `{ success: true, data: { job: JobJson-bez-notatek-i-protokołu, share: { recipientName, expiresAt }, canProtocol: false, canProgress: false } }` + nagłówki powyżej; inkrementuje `open_count`/`last_opened_at`. 404 `{success:false,error:"Link nieaktywny"}` dla każdego nieważnego tokenu.
- (opcjonalnie) `GET /api/share/:token/weather` / `distance` — NIE w pierwszej wersji.

# ETAP 2 (2026-10-20): link „do pracy” — notatki + Rozpocznij/Zakończ

Decyzja użytkownika: odbiorca linku ma móc **tworzyć i edytować swoje notatki oraz rozpoczynać i kończyć zlecenie**. Zmienia to model „tylko odczyt” z etapu 1 — poniższe przejmuje pierwszeństwo.

## Zasady
- **Per link przełącznik uprawnień** (kolumna `can_work INTEGER NOT NULL DEFAULT 0`, migracja **0118** — uwaga na `when` jak przy 0117; istniejące linki zostają tylko-do-odczytu). W modalu: segment „Tylko podgląd” / „Może pracować (notatki, start/koniec)”, **domyślnie „Może pracować”**. `ShareRow` dostaje `canWork: boolean`; POST przyjmuje `canWork?: boolean`.
- **Autor.** Technik-link: działa „jako” ten technik; gość: jako `recipientName`. Etykieta autora (snapshot `userLabel` notatki i wpisu w activity_log) = `"<recipientName> (link)"`. Do pól wymagających `user.id` (MutationCtx, FK) użyć `created_by_user_id` linku (twórcy) — ale w etykiecie NIGDY nie pokazywać twórcy jako autora. Notatka zapisuje `share_id` (nowa kolumna w tabeli notatek wydarzeń, w 0118) — to jest „moja notatka”.
- **Widoczność notatek:** odbiorca widzi i edytuje/usuwa TYLKO notatki utworzone przez ten sam link (`share_id` = id linku). Cudzych notatek (biuro, technicy) nie widzi i nie dotyka (404 przy próbie). Wewnętrzna rozmowa nadal ukryta.
- **Start/Koniec:** dokładnie ta sama semantyka co `POST /technik/jobs/:id/start|finish` (reużyj `setEventProgress` i walidacje z `src/routes/technik.ts`, w tym zachowanie przy statusie „wykonane” i `onEventUpdated`). Bez „reopen” i bez protokołu w tym etapie. `canProgress` w odpowiedzi publicznej = `can_work` i typ pozwala (jak flagi w technik).
- **Bezpieczeństwo zapisu:** każda mutacja ponownie sprawdza token (aktywny, nie wygasł, wydarzenie nie usunięte, `can_work=1`) → inaczej to samo 404 „Link nieaktywny”; limit zapisów per IP i per link (np. 30/min); rozmiar tekstu notatki i liczba/rozmiar plików jak w panelu technika; każda mutacja `publish(...)` dla otwartych kart biura i wpis w `activity_log` z etykietą „(link)”. Token w ścieżce, nagłówki jak w odczycie (`no-referrer`, `no-store`, `noindex`), brak CORS-credentials.

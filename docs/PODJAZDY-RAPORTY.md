# Raporty z podjazdów (CMA → zakładka „Podjazdy”)

Status: kontrakt zapisany 2026-10-15, implementacja w toku (backend + frontend osobnymi agentami).

## Źródło
Mailem przychodzi `raport_z_podjazdow_<data>_<godz>_<hash>.xlsx` (przykład w korzeniu repo: `raport_z_podjazdow_2026-10-08_07_30_276ac72a735a947.xlsx`, nie commitować).
To **dziennik zdarzeń z systemu monitoringu**: jeden wiersz = jeden krok obsługi; wiersze zdarzenia łączy `Identyfikator zdarzenia`. Kolumny (36): Identyfikator 1-3, Kategoria obiektu, Nazwa, Ulica, Nr, Kod pocztowy, Miasto, Grupy, Zdarzenie (opis alarmu), Data/Godzina zdarzenia, Data/Godzina zakończenia zdarzenia, Klasyfikacja (tryb, np. „07 - WYSŁANIE -PATROL”), Użytkownik, Data obsługi, Godzina obsługi, Obsługa (treść kroku, bywa wielolinijkowa), Użytkownik rozpoczynający/kończący obsługę, Załoga, Godzina wyjazdu, Godzina przyjazdu, Godzina odjazdu, Pora dnia, Maksymalny czas dojazdu, Czas dojazdu, Spóźnienie, Status dojazdu, Przedział spóźnienia, Typ zdarzenia, Identyfikator zdarzenia, Zdarzenie manualne, Typ usługi.

Pułapki z próbki: kolumny Załoga/Godziny wyjazdu-przyjazdu-odjazdu są powielone na każdym wierszu zdarzenia; „Godzina przyjazdu” bywa przed „Godziną wyjazdu” (dane z systemu, nie poprawiać, tylko oznaczyć anomalię); wiersze `Obsługa` mogą mieć czas sprzed rozpoczęcia zdarzenia; pola puste = pusty string; to samo zdarzenie może przyjść w kolejnym raporcie (dedup po `Identyfikator zdarzenia`).

## Definicja podjazdu
Zdarzenie (grupa wierszy o tym samym `Identyfikator zdarzenia`), w którym `Załoga` jest niepusta lub jest krok „Wysłano PI”. Reszta zdarzeń z raportu: zapisujemy **jako „bez wyjazdu”** (flaga `has_patrol=0`), lista domyślnie pokazuje tylko podjazdy, filtr „Pokaż bez wyjazdu”.

## Model danych (migracja 0114+, ostrożnie z `when` — zob. memory migration-when-ordering)
- `patrol_reports` — jeden import pliku: id, source (`mail`|`upload`), file_name, file_hash (UNIQUE), mail_message_id, received_at, events_total, events_new, events_updated, created_at.
- `patrol_events` — jedno zdarzenie: id, event_ref (UNIQUE = Identyfikator zdarzenia), report_id (ostatni raport), object_id (nullable → objects), object_name, street, no, postal, city, groups, alarm_text (Zdarzenie), classification, event_type (Typ zdarzenia), manual (0/1), service_type, started_at, ended_at (ISO `YYYY-MM-DDTHH:MM:SS`), day_part, has_patrol, crew, departed_at, arrived_at, left_at, max_travel_min, travel_min, delay_min, travel_status, delay_bucket, operator (główny), anomalies (JSON array stringów), intervention_id (nullable → interventions, po „utwórz rozliczenie”), created_at, updated_at.
- `patrol_event_steps` — kroki: id, event_id, at (ISO), text, operator, kind (`start`|`dispatch`|`arrived`|`left`|`contact`|`ai`|`note`|`end`, wnioskowane z treści), seq.
Upsert po `event_ref`: nowy raport z tym samym zdarzeniem odświeża pola i kroki (kroki: replace).

## Dopasowanie obiektu
Po nazwie z raportu (normalizacja: lowercase, bez diakrytyków, bez spacji wielokrotnych) do `objects` (patrz jak robi to `src/utils/cma-import.ts` dla raportów kamer); brak dopasowania → `object_id=NULL`, UI pozwala wskazać obiekt ręcznie (własny `GET /pick/objects` jak w intervention-groups).

## API (backend, prefiks `/api/cma/podjazdy`, klucz uprawnień `cma/podjazdy`, dodać do `API_TAB_MAP` i `api.route` PRZED `/cma`)
- `GET /` ?from=&to=&q=&objectId=&crew=&status=(`all|late|ontime`)&withoutPatrol=0|1&matched=(`all|yes|no`)&sort=&dir=&page=&pageSize= → `{ items: PatrolEventRow[], total, stats: {count, late, avgTravelMin, crews:[{crew,count}]} }`
- `GET /:id` → `PatrolEventDetail` = wiersz + `steps[]` + `anomalies[]` + `report:{id,fileName,receivedAt}` + `object:{id,name}|null`
- `PATCH /:id` `{ objectId }` — ręczne przypisanie obiektu
- `POST /import` multipart `file` — ręczny upload xlsx (ten sam parser) → `{ reportId, eventsTotal, eventsNew, eventsUpdated, patrols }`
- `GET /reports` — lista importów; `GET /mail-status` — ostatni wynik skanu
- `POST /:id/intervention` — tworzy wpis w `interventions` (resolveTermFor; brak warunków → 400 z komunikatem), zapisuje `intervention_id`; reason = alarm_text, happenedAt = arrived_at||started_at
Typy `PatrolEventRow` (pola jak kolumny camelCase + `objectName`, `anomalies: string[]`) eksportuje backend w `src/types` i frontend powiela w `frontend/src/lib/api.ts`.

### API — doprecyzowanie po implementacji backendu (2026-10-15, obowiązuje)
- Wszystkie odpowiedzi w konwencji projektu: `{ success: true, data: … }` / `{ success: false, error }`. Kształty powyżej to zawartość `data`.
- Lista: `GET /api/cma/podjazdy?…` **bez ukośnika na końcu** (Hono strict — `/api/cma/podjazdy/` daje 404). Domyślnie `sort=startedAt&dir=desc&page=1&pageSize=50` (max 200). `sort` ∈ `startedAt|objectName|crew|travelMin|delayMin|arrivedAt|city|operator` (inny → 400); NULL-e zawsze na końcu. `from`/`to` = `YYYY-MM-DD` po `startedAt`, `to` włącznie. `stats` liczone z całego przefiltrowanego zbioru (nie strony): `{count, late, avgTravelMin (tylko travelMin ≥ 0, 1 miejsce po przecinku, null gdy brak), crews:[{crew,count}] malejąco}`.
- `PatrolEventRow` ma dodatkowo: `linkedObjectName: string|null` (nazwa z kartoteki, gdy `objectId`), `late: boolean` (wyliczone przy imporcie), `interventionId`, `createdAt`, `updatedAt`; `objectName` = nazwa z raportu. Pełny typ: `src/types/index.ts` (`PatrolEventRow`, `PatrolEventStepDto`, `PatrolEventDetail`).
- `status=ontime` = podjazd i `late=0` (także gdy brak danych o czasie dojazdu).
- `GET /:id` → `PatrolEventDetail` = wiersz + `steps[{id,at,text,operator,kind,seq}]` (po `seq`, czyli po czasie) + `report:{id,fileName,receivedAt,source}|null` + `object:{id,name}|null`. `receivedAt` to pełne ISO z `Z` (UTC); czasy zdarzeń są lokalne bez strefy.
- `PATCH /:id` `{ objectId: number|null }` → zwraca `PatrolEventDetail`; 400 zły obiekt, 409 gdy podjazd ma już rozliczenie i obiekt miałby się zmienić.
- `POST /import` (multipart `file`, .xlsx/.xls, limit 20 MB) → 201 `{reportId, eventsTotal, eventsNew, eventsUpdated, patrols}`; **409** `{error, data:{reportId}}` gdy identyczny plik (sha256) już był; 400 gdy to nie raport z podjazdów (komunikat po polsku w `error`).
- `GET /reports` → `{items: PatrolReport[]}` (ostatnie 100, malejąco). `GET /mail-status` → `{importEnabled, lastCheckAt, lastCheckStatus, lastCheckError, lastReport: PatrolReport|null (ostatni z maila), recent: [{id,subject,fileName,status,detail,createdAt}] (10 ostatnich wpisów cma_mail_log dla raport_z_podjazd*)}`.
- `GET /pick/objects?q=` → `{items:[{id,name,address,city,contractorName}]}` (max 30) — jak w grupach interwencyjnych.
- `POST /:id/intervention` → 201 `{interventionId, event: PatrolEventDetail}`; 400: zdarzenie bez wyjazdu / bez obiektu („Najpierw przypisz obiekt z kartoteki”) / brak warunków („Obiekt nie ma warunków grupy interwencyjnej obowiązujących w tym dniu”); 409 gdy rozliczenie już istnieje. Interwencja: `happenedAt` = `(arrivedAt ?? startedAt)` do minut, `reason` = alarm (500 zn.), `reportedBy` = operator, `notes` = patrol + nr zdarzenia + czas dojazdu.
- Uprawnienia: GET = `view`, reszta = `edit` na `cma/podjazdy` (tabPermissionGuard); rozliczenie nie wymaga klucza grup interwencyjnych.
